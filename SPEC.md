# `yflow` — итоговая спецификация

Единое имя по всему документу: **`yflow`** — бинарник, репозиторий, конфиг, Go-модуль. Короткий алиас `flow` возможен только как symlink в инструкции по установке и в спецификацию не входит.

---

## 1. Идентификация

- **Бинарник / репозиторий / модуль:** `yflow` (`github.com/<user>/yflow`).
- **Язык:** Go, один статически слинкованный бинарник под Linux/macOS/Windows.
- **Конфиг-файлы:** `./.yflow.yaml`, `$XDG_CONFIG_HOME/yflow/config.yaml` (fallback `~/.config/yflow/config.yaml`).
- **Установка:** `go install github.com/<user>/yflow@latest` + бинарные релизы на GitHub.

## 2. Назначение

Форматирование YAML-файлов + опциональная свёртка узлов в flow style с контролем **полной длины итоговой строки**.

Сценарии:
- **CI/CD** — `--check`, `--diff`, предсказуемые коды возврата, работа со `stdin`/`stdout`.
- **Локальная разработка** — `--write`, конфиг-файл, интеграция с редакторами.

## 3. Метрика и правило свёртки

**Единственная метрика:** полная длина строки, в которую превратился бы узел при свёртке.

```
full_line_length = len(indent) + len(prefix) + len(flow_repr(node))
```

где:
- `indent` — отступы по текущей позиции в документе;
- `prefix` — `"key: "` для значения в маппинге, `"- "` для элемента массива, `""` для корня;
- `flow_repr` — представление в каноническом формате (§4);
- длина в **рунах**, не в байтах.

**Правило:** узел сворачивается в одну строку тогда и только тогда, когда:

```
can_fold(node) && full_line_length ≤ inline_limit
```

- `inline_limit` = `--inline-limit`, по умолчанию **255**.
- Свёртка активна **только** при `--inline`.
- Если узел уже inline, но не проходит по лимиту или `can_fold` = false — он **разворачивается** в block style.

## 4. Канонический формат flow

Применяется **всегда** — и при `--inline`, и при обычном форматировании.

```yaml
{ a: [ 1, 2 ], b: { c: 3 } }
```

Правила:
- `{`/`[` — один пробел справа; `}`/`]` — один пробел слева.
- Разделитель элементов — `, ` (запятая + пробел).
- Пары: `key: value` (пробел после двоеточия).
- **Пустые коллекции:** `[]` и `{}` без внутренних пробелов.
- Скаляры — через стандартный скалярный эмиттер (корректные кавычки, экранирование).

> ⚠️ Стандартный `gopkg.in/yaml.v3` эмиттит `{a: [1, 2]}` — это не настраивается параметрами. Требуется **собственный flow-эмиттер**: рекурсивный обход `*yaml.Node`, скаляры — через `yaml.Marshal(node)`, коллекции — собственный обходчик. Post-processing строки недопустим (ломается на литералах, содержащих `{}[],:`).

## 5. Алгоритм

**Фаза 1 — `flow_repr(node)` снизу вверх.** Рекурсивно строит flow-представление узла: скаляр → строка с кавычками при необходимости; seq/map → по §4. Вычисляется один раз на узел.

**Фаза 2 — решение и вывод сверху вниз.** Для каждого узла в контексте `(indent, prefix)`:

1. `candidate = indent + prefix + flow_repr(node)`.
2. Если `can_fold(node)` и `len(candidate) ≤ inline_limit` → вывод одной строкой.
3. Иначе — block style, рекурсивный спуск к детям с новым `(indent, prefix)`.

`can_fold(node)` истинно, если:
- `node` — коллекция (seq или map);
- в поддереве **нет комментариев** **или** включён `--strip-comments`.

Следствия:
- вложенные коллекции сворачиваются рекурсивно; родитель сворачивается только если и он, и его дети уложились в лимит;
- существующие inline-узлы разворачиваются, если не проходят по лимиту;
- корневой маппинг, уложившийся в лимит, свернётся целиком — **оставляем как есть**;
- **скаляры никогда не разворачиваются**; длина родителя-коллекции считается по фактическим длинам скаляров.

## 6. Комментарии

- По умолчанию узел с комментарием в поддереве **не сворачивается**.
- `--strip-comments` снимает блокировку **только** у узлов, которые фактически сворачиваются; комментарии вне свёрнутых узлов сохраняются.
- Если с флагом узел всё равно не уложился в лимит — комментарии в нём **сохраняются**.
- Комментарии не входят в длину (они не эмитятся в flow-форме).

## 7. Поведение без `--inline`

- Свёртка/развёртка не выполняется.
- Нормализуются отступы (`--indent`, по умолчанию 2).
- **Каноническая расстановка пробелов в существующих flow-узлах применяется всегда** (§4).
- Стили block-узлов и комментарии сохраняются.

## 8. CLI

| Флаг | Назначение | По умолчанию |
|---|---|---|
| `--inline` | Включить свёртку/развёртку | выкл. |
| `--inline-limit=N` | Лимит на **полную** длину строки при свёртке | 255 |
| `--strip-comments` | Разрешить удаление комментариев внутри сворачиваемых узлов | выкл. |
| `--indent=N` | Размер отступа | 2 |
| `--write`, `-w` | Перезапись файлов | выкл. |
| `--check`, `--lint` | Проверка без изменений | выкл. |
| `--diff` | Unified diff в `stdout` | выкл. |
| `--recursive` | Обход директорий | выкл. |
| `--config=PATH` | Конфиг-файл | авто (§1) |
| `--quiet` | Только ошибки | выкл. |

**Источники ввода:** позиционные пути, `-` / `--stdin`, `--recursive` для директорий с фильтром `.yaml`/`.yml`.

**Вывод:** по умолчанию `stdout`; `-w` — перезапись; со `stdin` — только `stdout`.

## 9. Нефункциональные требования

- **Ошибки:** plain text в `stderr`, формат `file.yaml:12:5: error: unexpected mapping start`.
- **Коды возврата:** `0` успех; `1` требуется переформатирование (`--check`); `2` I/O; `3` синтаксис YAML; `4` конфиг/флаги.
- **Идемпотентность:** повторный запуск не меняет выход.
- **Многодокументные YAML** (`---`) — обрабатываются независимо.
- **Множественные файлы** — независимо; в `--check` код `1`, если хотя бы один файл требует изменений.
- **`--check` + `--diff`:** unified diff в `stdout`, заголовки `--- file` / `+++ file`.
- **Якоря/алиасы (`&`/`*`)** — специально не обрабатываются (по согласованию).
- **Производительность:** обработка файлов до нескольких МБ без избыточного потребления памяти (работа через `yaml.Node`).

## 10. Известные ограничения и риски

1. **Собственный flow-эмиттер обязателен** — стандартный `yaml.v3` не даёт нужного формата. Основная «нестандартная» часть реализации; требует отдельного набора юнит-тестов на скаляры с кавычками, экранированием, `null`, датами, многострочными строками.
2. **Сохранение комментариев и якорей при round-trip** ограничивает манипуляции с AST — нельзя пересобирать документ с нуля.
3. **Имя `yflow`** однозначно и не конфликтует с популярными инструментами (`yamlfmt`, `yamllint`, `yam`); короткий `flow` — только как опциональный symlink, документируется отдельно.

## 11. План реализации

**Архитектура пакетов:**
- `internal/parse` — чтение файла/`stdin`, декодирование в `*yaml.Node` (с сохранением `HeadComment`/`LineComment`/`FootComment`);
- `internal/flow` — `flow_repr`, `can_fold`, канонический эмиттер (главный модуль с тестами);
- `internal/format` — фаза 2 (свёртка/развёртка/нормализация отступов), запись;
- `internal/cli` — флаги, режимы (`--check`/`--diff`/`--write`), коды возврата;
- `internal/config` — загрузка `.yflow.yaml`.

**Тестовая матрица:**
- свёртка/развёртка на вложенных seq/map, пороги 254/255/256;
- кириллица/эмодзи в значениях (подсчёт в рунах);
- комментарии в разных позициях, `--strip-comments` on/off, с/без свёртки;
- пустые `[]`/`{}`;
- многодокументные файлы, несколько файлов;
- идемпотентность: `format(format(x)) == format(x)`;
- корневой маппинг, уложившийся в лимит;
- скаляры с кавычками/экранированием внутри fold;
- `--check` (коды 0/1), `--diff`.

**MVP (v0.1):**
- `--inline` + `--inline-limit` + `--strip-comments`;
- `--indent`, `stdin`/файл, `--write`, `--check`, `--diff`.

**Итерация 2 (v0.2):**
- `--recursive`, конфиг-файл, рецепты интеграции с редакторами (VS Code, Neovim), публикация бинарных релизов.
